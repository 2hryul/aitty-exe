# ARCH — AI 채팅 자동스크롤 수정 계획

---

## 1. 현상

AI 응답이 길어질 때, 사용자가 위로 스크롤해도 화면이 자동으로 아래로 내려감.
wheel 이벤트 기반 Smart Auto-Scroll을 구현했으나 동작하지 않음.

---

## 2. 근본 원인: 조건부 렌더링으로 인한 이벤트 리스너 미등록

### 문제 코드 (ChatPanel.tsx)

```tsx
// ── 구조적 문제: 두 개의 return 분기 ──

if (messages.length === 0) {
  // 분기 1: 빈 상태 → scrollRef 미할당
  return (
    <div className="chat-panel chat-panel-empty">  // ← ref 없음!
      <div className="chat-empty-message">...</div>
    </div>
  )
}

// 분기 2: 메시지 존재 → scrollRef 할당
return (
  <div className="chat-panel" ref={scrollRef}>  // ← ref 있음
    {messages.map(...)}
    <div ref={bottomRef} />
  </div>
)
```

### 실행 순서

```
1. 앱 시작 → messages = [] → 분기 1 렌더링
   ↓
2. useEffect(() => { ... }, []) 실행 — 최초 1회만 실행
   → scrollRef.current = null (분기 1에는 ref가 없으므로)
   → el = null → return (리스너 등록 안 됨!)
   ↓
3. 사용자가 메시지 전송 → messages.length > 0 → 분기 2 렌더링
   → scrollRef.current = <새 div> (이제 설정됨)
   ↓
4. 하지만 useEffect([], []) 의존성이 [] 이므로 재실행 안 됨
   → wheel 이벤트 리스너는 영원히 등록되지 않음!
   → userScrolledUpRef는 항상 false
   → 모든 스트리밍 청크에서 무조건 scrollTop = scrollHeight 실행
```

### 결론

> **wheel 이벤트 리스너가 한 번도 등록되지 않아 사용자 스크롤을 감지할 수 없다.**
> Smart Auto-Scroll 로직 자체는 정확하나, 이벤트 리스너가 달리지 않아 동작 불가.

## 3. 수정 계획

### 변경 파일: `ChatPanel.tsx` (1개 파일만)

### 핵심 수정: 조건부 렌더링 제거 → 단일 스크롤 컨테이너 항상 유지

**변경 전 (2개 분기):**
```tsx
if (messages.length === 0) {
  return (<div className="chat-panel chat-panel-empty">...)  // ref 없음
}
return (<div className="chat-panel" ref={scrollRef}>...)      // ref 있음
```

**변경 후 (단일 컨테이너):**
```tsx
return (
  <div className="chat-panel" ref={scrollRef}>
    {messages.length === 0 ? (
      <div className="chat-empty-state">...</div>
    ) : (
      <>
        {messages.map(...)}
        <div ref={bottomRef} />
      </>
    )}
  </div>
)
```

**효과:**
- `scrollRef`가 최초 마운트부터 항상 실제 DOM 요소를 가리킴
- `useEffect([], [])` 실행 시 `scrollRef.current !== null`
- wheel 이벤트 리스너가 정상 등록됨
- Smart Auto-Scroll 로직이 의도대로 동작
