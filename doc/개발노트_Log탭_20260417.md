# 개발노트 — Log 탭 (SSH 로그 → AI 분석) — v0.2.9

## 2026-04-17 작업 내역

### 작업 내용
SSH 접속된 서버의 로그를 가져와 AI가 분석하는 Log 전용 탭을 신설. Chat/CLI/Security 옆에 4번째 탭으로 배치. 사용자가 지정한 로그 파일의 크기가 현재 AI 모델의 컨텍스트 예산을 초과하면 경고 모달로 **분할 분석 / 뒤쪽 자르기 / 모델 전환** 3옵션을 제시. 무음 트렁케이션은 하지 않음(사용자가 잘린 것을 모르는 채 오판 방지).

### 결정 사항

**예산 테이블 (프로바이더별 byte 상한)**
| 모델 | 예산 |
|------|-----|
| Claude Opus/Sonnet 4.x | 600 KB |
| Claude Haiku 4.5 | 400 KB |
| OpenAI gpt-4o | 350 KB |
| OpenAI gpt-4o-mini / gpt-3.5 | 200 KB |
| Gemini 1.5 Pro | 1 MB (IPC 상한) |
| Gemini 1.5/2.0 Flash | 800 KB |
| Ollama (기본) | 24 KB |
| Ollama 32k / qwen2.5 | 90 KB |
| 미지의 모델 | 50 KB (폴백) |

C#과 TS 양쪽에 동일한 테이블 유지. 프론트 미러는 모델 전환 시 네트워크 왕복 없이 즉시 경고 계산용.

**분할 분석 체인**
- `chunkBytes = budget × 0.8` 크기로 UTF-8 바이트 기준 `\n` 경계 분할
- 이전 청크 AI 요약의 앞 `budget × 0.1` 바이트를 다음 청크 system 프롬프트 부록으로 연결
- 마지막에 "청크 요약 종합" 1회 추가 호출
- 진행률은 `logs:chunk-progress { index, total, bytes }` 이벤트로 발송

**무음 트렁케이션 금지**
`status > ok`일 때 자동 모달 오픈. `reject` 상태에선 닫기 비활성화 → 사용자가 3옵션 중 선택해야 진행.

**클라이언트 측 자르기**
"뒤쪽 자르기" 선택 시 이미 수집된 payload를 `truncateTailBytes`로 UTF-8 안전 슬라이스. 네트워크 왕복 없음. Continuation byte(`0x80..0xBF`) 보정 + 첫 `\n` 이후부터 사용.

**이벤트 라우팅 버그 예방**
`logs:chunk-progress`는 같은 `msg.id`로 도착하지만 pending 프로미스를 resolve 해서는 안 됨. ipcBridge에서 `:chunk` 분기 직후, `pending.get` 이전에 별도 분기로 가로채 `progressListeners`로 라우팅.

**에러 메시지 sanitize**
백엔드 `InvalidOperationException` 메시지가 서버 경로/예외 클래스명을 UI로 새는 위험 방지. 화이트리스트 매핑 + 원본 에러는 `logger.error`로만 보존.
