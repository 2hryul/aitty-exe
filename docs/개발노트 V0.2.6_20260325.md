## 2. 버그 수정 상세

### 2.1 WebView2 `0x8007139F` 초기화 실패 대응

**파일**: `MainWindow.xaml.cs`

비정상 종료 후 `EBWebView/SingletonLock` 잠금 파일 잔류 → 앱 재시작 시 COMException 크래시.

**수정**: `InitializeWebView2Async()` 메서드 분리, 3단계 복구 전략:

```
[1차] CleanWebView2LockFiles() — *lock*, *.tmp 삭제 → 1.5초 대기 → 재시도
[2차] 새 타임스탬프 폴더(WebView2_yyyyMMdd_HHmmss) 폴백
[3차] 예외 전파 (기존 동작)
```

### 2.2 스트리밍 중 "응답 없음" (WPF UI Freeze)

**파일**: `IpcHandler.cs` (3개 메서드)

**원인**: AI 스트리밍 청크를 `Dispatcher.InvokeAsync(Normal)` (우선순위 9)로 전송 → `Input` (우선순위 5)보다 높아 마우스/키보드 이벤트가 큐에서 밀림 → Windows가 "응답 없음" 판정.

**수정**: `DispatcherPriority.Background` (우선순위 4) 로 변경. Input 이벤트가 청크 사이에 처리됨.

```csharp
// 변경 전 (Normal, priority 9 > Input priority 5)
_ = _webView.Dispatcher.InvokeAsync(() => PostChunk(), Normal);

// 변경 후 (Background, priority 4 < Input priority 5)
lastChunkOp = _webView.Dispatcher.InvokeAsync(() => PostChunk(), Background);
```

### 2.3 스트리밍 완료 후 빈 말풍선 (청크 순서 역전)

**파일**: `IpcHandler.cs` — `HandleAiStream`, `HandleAiAnalyzeSsh`, `HandleAiSuggestCommand`

**원인**: Background 우선순위 청크가 큐에서 대기 중인데, 최종 결과(`ai:stream:result`)가 Normal 우선순위로 먼저 도달 → React에서 `isProcessingRef = false` → 뒤늦게 도착한 청크 전부 스킵.

```
[버그 흐름]
청크 50개 → Background 큐 대기
최종 결과 → Normal 우선순위 → React 즉시 수신
→ isProcessingRef = false → 청크 50개 도착 시 return → 빈 말풍선
```

**수정**: 마지막 `DispatcherOperation`을 추적, 최종 결과 반환 전 `await lastChunkOp.Task` — Background 큐는 FIFO이므로 마지막 완료 = 전체 완료 보장.

```csharp
DispatcherOperation? lastChunkOp = null;
var response = await SendStreamingAsync(msg, chunk => {
    lastChunkOp = Dispatcher.InvokeAsync(() => PostChunk(chunk), Background);
}, ct);

// 모든 청크 전달 완료 후 최종 결과 반환
if (lastChunkOp is not null)
    try { await lastChunkOp.Task; } catch { }

return new { content = response.Content, done = true };
```

### 2.4 위험 명령어 Run 버튼 차단 미동작

**파일**: `ChatPanel.tsx`, `CodeBlock.tsx`, `chat.css`, `commandSafety.ts`

**원인 3가지**:

| # | 원인 | 영향 |
|---|------|------|
| 1 | 언어 태그 없는 코드 블록 → `<code>` 렌더링 (Run 버튼 없음) | 안전 검사 자체가 실행 안 됨 |
| 2 | `isShellLang` 목록이 좁음 (`terminal`, `cmd` 등 미인식) | 비표준 태그 사용 시 검사 스킵 |
| 3 | `.code-action-danger` CSS에 `pointer-events: none` 미설정 | 일부 환경에서 disabled 버튼 클릭 가능 |

**수정**:

```tsx
// ChatPanel: 멀티라인이면 언어 태그 없어도 CodeBlock 렌더링
const isBlock = match !== null || codeStr.includes('\n')
if (isBlock) return <CodeBlock language={match ? match[1] : ''} ... />

// CodeBlock: isShellLang 목록 확장
const isShellLang = !language || ['bash','sh','zsh','shell','console','text',
  'terminal','linux','cmd','command','powershell','fish'].includes(...)

// CSS: danger 버튼 이중 차단
.code-action-danger { pointer-events: none; cursor: not-allowed; }
```

## 3. 신규 기능

### 3.1 🛡 보안점검 탭 (`SecurityPanel.tsx`)

**파일**: `SecurityPanel.tsx` (신규), `AITerminal.tsx`, `IpcHandler.cs`, `ipcBridge.ts`, `chat.css`

Linux 서버 보안취약점 점검/조치를 위한 전용 탭.

**구조**:
```
common.sh  (공통 라이브러리)
    ↓ source
check.sh   ←── 점검 전용
fix.sh     ← run_check_after_fix() 으로 check.sh 호출
```

**주요 기능**:

| 기능 | 설명 |
|------|------|
| 📁 폴더 선택 | 로컬에서 .sh 3개 파일이 있는 폴더를 선택 |
| 📤 업로드 | SCP로 `~/security_check/` 에 3개 파일 전송 |
| ▶ 점검 실행 | `sudo bash check.sh` → 결과를 실시간 파싱 |
| 🔧 조치 실행 | `sudo bash fix.sh` → check.sh 재호출로 교차 검증 |
| 📊 결과 표시 | 항목별 PASS/FAIL 상태 + AI 분석 연동 |

**IPC 프로토콜 추가**:
```
security:select-folder  → 네이티브 폴더 선택 다이얼로그
security:upload         → SCP 파일 전송
security:run-check      → SSH 명령 실행 + 실시간 출력
security:run-fix        → SSH 조치 명령 실행
```

**보안 요구사항**:
- sudo 권한: 사용자에게 비밀번호 요청
- 세션 유지: SSH 세션 동안만 sudo 유효
- 배포 위치: `~/security_check/` (home 디렉토리)
